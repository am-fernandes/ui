# Textos e idioma

Todo texto que um componente escreve por conta própria (placeholder, botão, nome acessível, mensagem de vazio, contagem) vem de um objeto `labels` com padrão em pt-BR. O app troca só o que precisa.

Componentes com um texto só recebem uma prop direta: `Dialog` e `Sheet` (`closeLabel`, "Fechar"), `AlertDialog` (`confirmLabel`, `cancelLabel`), `Collapsible` (`triggerLabel`), `DateRangePicker` (`placeholder`), `Select`/`Combobox` (`placeholder`).

## Troca parcial

Passe só as chaves que mudam; as outras continuam do padrão.

```tsx
import { DataTable, type ColumnDef } from "@amfernandesinc/ui"

type Corretor = { nome: string; creci: string }
const columns: ColumnDef<Corretor>[] = [
  { accessorKey: "nome", header: "Nome" },
  { accessorKey: "creci", header: "CRECI" },
]

export function Corretores({ data }: { data: Corretor[] }) {
  return (
    <DataTable
      aria-label="Corretores"
      columns={columns}
      data={data}
      searchableColumns={["nome", "creci"]}
      labels={{
        search: "Buscar corretor por nome ou CRECI",
        empty: "Nenhum corretor com esse nome ou CRECI.",
        rowCount: (filtrados, total) =>
          filtrados === total ? `${total} corretor${total === 1 ? "" : "es"}` : `${filtrados} de ${total} corretores`,
      }}
    />
  )
}
```

## Outro idioma

Monte o objeto completo a partir do padrão e reutilize. Tipado como `XLabels` (não `Partial`), o TypeScript acusa quando a lib ganhar uma chave nova que a tradução ainda não tem.

```tsx
import {
  type ColumnDef,
  DataTable,
  type DataTableLabels,
  Pagination,
  type PaginationLabels,
  defaultDataTableLabels,
  defaultPaginationLabels,
} from "@amfernandesinc/ui"

export const dataTableEn: DataTableLabels = {
  ...defaultDataTableLabels,
  search: "Search…",
  empty: "No results.",
  rowCount: (filtered, total) => (filtered === total ? `${total} records` : `${filtered} of ${total} records`),
}

export const paginationEn: PaginationLabels = {
  ...defaultPaginationLabels,
}

type Row = { id: string; name: string }
const columns: ColumnDef<Row>[] = [{ accessorKey: "name", header: "Name" }]

export function EnglishList({ rows, page, setPage }: { rows: Row[]; page: number; setPage: (p: number) => void }) {
  return (
    <div className="space-y-4">
      <DataTable aria-label="Customers" columns={columns} data={rows} labels={dataTableEn} />
      <Pagination page={page} onPageChange={setPage} totalPages={10} labels={paginationEn} />
    </div>
  )
}
```

Chaves que dependem de quantidade ou de um nome são **funções** (`rowCount(filtrados, total)` e `pageIndicator(pagina, total)` da `DataTable`, `removeFile(nome)` do `FileUpload`, `characterCount(n, max)` do `Textarea`, `create(termo)` do `Combobox`, `range(de, ate, total)` da `Pagination`): é nelas que entram plural, gênero e números formatados. No `Combobox` múltiplo, a concordância do gatilho ("3 corretores") vem da prop `selectedCountLabel`.

## Datas e números de outro idioma

- `Schedule` tem `locale` (`"pt-BR"` padrão; `"en-US"`, `"es"`…) para nomes de dias, meses e formatos. Os textos fixos continuam em `labels`.
- `Calendar`, `DateInput` e `DateRangePicker` mostram meses e dias da semana em pt-BR (do react-day-picker), mesmo com `labels` trocados.
- Os helpers de dinheiro e data formatam em pt-BR (`formatBRL`, `formatDate`); para outro idioma, use `Intl` no app.
- O "obrigatório" lido junto do rótulo existe só onde o controle não anuncia `required` sozinho: `DateRangePicker` (um botão) e `TimePicker` (o grupo), com o texto em `labels.required`. Nos outros campos, o próprio controle diz que é obrigatório.

## No seu código

- Nada de texto pt-BR fixo dentro de componentes compartilhados que precisam ser traduzíveis: receba por props ou de um objeto de textos do app.
- Textos de tela (títulos, botões, mensagens) seguem o tom da lib: frases curtas, verbo no infinitivo nos botões ("Salvar proposta"), mensagens que dizem o que fazer ("Informe o CPF.").
