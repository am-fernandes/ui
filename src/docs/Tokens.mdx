# Tokens

Esta página documenta os **tokens não-cromáticos** declarados em `src/styles/tokens.css`. Para tokens de cor, veja [Colors](?path=/docs/foundations-colors--docs).

A filosofia é simples: cada propriedade visual do design system passa por um token CSS (`var(--*)`) e por um utilitário Tailwind correspondente. Isso permite que o consumidor use `rounded-md`, `duration-fast`, `z-popover` direto no JSX, sem nunca hardcodear valores.

## Radius

Três níveis, por papel: `--radius-inner` (4px), `--radius-element` (8px) e `--radius-container` (12px), com os utilitários `rounded-inner`, `rounded-element` e `rounded-container`. A escala do Tailwind cai neles: `rounded-xs`/`rounded-sm` → inner, `rounded-md` → element, `rounded-lg` até `rounded-4xl` → container.

A explicação completa, a lista por componente e a regra do concêntrico estão em [Radius](?path=/docs/foundations-radius--docs).

## Motion

Durações e curvas copiadas do Astryx. A duração segue o **peso visual** do que se move, em três faixas; cada faixa tem um mínimo e um máximo. Tudo que **sai** usa `--duration-exit` (a faixa rápida) com a curva que acelera: a saída é sempre mais curta que a entrada.

| Token | Valor | Onde |
|---|---|---|
| `--duration-fast-min` | `130ms` | |
| `--duration-fast` | `175ms` | hover e pressed (padrão de todo `transition`), Tooltip, DropdownMenu, Accordion, Collapsible |
| `--duration-fast-max` | `230ms` | |
| `--duration-medium-min` | `310ms` | Popover, Tour (entrada) |
| `--duration-medium` | `410ms` | Sheet, menu mobile do AppShell (entrada e saída) |
| `--duration-medium-max` | `550ms` | Dialog, AlertDialog e o backdrop (entrada) |
| `--duration-slow-min` | `730ms` | |
| `--duration-slow` | `975ms` | movimento contínuo |
| `--duration-slow-max` | `1300ms` | |
| `--duration-exit` | `= --duration-fast` | toda saída |

| Curva | Valor | Uso |
|---|---|---|
| `--ease-standard` | `cubic-bezier(0.24, 1, 0.4, 1)` | entradas e mudanças de estado (desacelera) |
| `--ease-exit` | `cubic-bezier(0.3, 0, 0.6, 0.6)` | saídas (acelera) |

As curvas vêm junto com as durações porque uma não funciona sem a outra: a `--ease-standard` anda quase tudo no começo e passa o resto assentando, então 550ms ainda parecem rápidos.

No Tailwind: `duration-(--duration-fast) ease-(--ease-standard)`. Os overlays usam as combinações prontas de `src/overlays/_internal/animations.ts` (`motionTooltip`, `motionMenu`, `motionPopover`, `motionDialog`, `motionSheet`).

`--motion-fast`, `--motion-default`, `--motion-slow` e `--motion-slowest` continuam definidos por uma versão, apontando para o token novo de cada papel, e estão **deprecated**.

### `prefers-reduced-motion`

No fim de `tokens.css` há um override global que respeita `@media (prefers-reduced-motion: reduce)` — todas as animações e transições caem para `0.01ms` quando o sistema operacional pede menos movimento. Isso vale para qualquer componente, incluindo os de terceiros que usem `transition` ou `animation` CSS.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

## Foco

Dois visuais, os dois copiados do Astryx: um anel para os controles e um visual próprio para os campos.

### Controles

**Um anel só** para botões, checkbox, switch, abas e links: contorno de **2px** sólido na cor `--ring` (o azul funcional: marinho-500 no claro, marinho-300 no escuro), **3px** afastado da borda, só em `:focus-visible` (quem usa o teclado vê; um clique de mouse num botão não acende o anel).

```css
--focus-outline-width: 2px;
--focus-outline-style: solid;
--focus-outline-color: var(--ring);
--focus-outline-offset: 3px;
```

| Utilitário | Uso |
|---|---|
| `focus-visible:focus-outline` | botões, checkbox, switch, abas, links |
| `focus-visible:focus-outline-inset` | células, linhas e itens dentro de um contêiner que cortaria o anel de fora |

O mesmo anel é o padrão de qualquer elemento focável (`:focus-visible` no `@layer base`), então um link ou um botão do app consumidor já sai igual. Dentro de um fundo de status (um `Alert` de erro, por exemplo) o anel usa a cor do texto dele, porque o azul não teria contraste ali.

### Campos

Input, Textarea, os inputs brasileiros, MultiInput, TimePicker, os selects de paginação e os gatilhos de Combobox, DateInput e DateRangePicker usam o visual de campo do Astryx (`field-states`), em qualquer foco, inclusive com clique:

| Estado | Visual |
|---|---|
| repouso | borda sólida `--input` |
| hover (só com mouse, nunca desabilitado) | anel interno de 2px na cor da borda a 30% |
| foco | borda `--ring` e anel interno de 2px dela a 20% (`--field-focus-ring`; 25% no escuro) |
| erro (`border-destructive-text field-error`) | borda vermelha, também no foco; hover com o vermelho a 30% |

O `field-states` vai no elemento que desenha a borda: a caixa, quando o `<input>` fica dentro dela, ou o próprio `<input>`. Com toque, a troca é instantânea (sem fade enquanto o teclado sobe).

## Estados

Hover e pressed são uma **camada translúcida** da cor do texto do próprio controle, pintada por cima do fundo. A mesma regra serve para qualquer variante: escurece um fundo claro e clareia um fundo escuro.

```css
--state-hover-opacity: 5%;
--state-pressed-opacity: 10%;
```

| Utilitário | Uso |
|---|---|
| `state-layer` | hover (só em dispositivo com mouse) e pressed; nunca num controle desabilitado |
| `state-hover` / `state-pressed` | a mesma camada para estados que não são o ponteiro: `focus:state-hover` num item de menu, `aria-selected:state-hover` num item de combobox |

O **botão principal** é a exceção: em vez da camada, ele troca de tom (`--primary-hover` e `--primary-pressed`), porque 5% de branco sobre o marinho-950 quase não aparece. No claro, os dois tons caminham para o marinho das marcas.

Pressed também encolhe o botão para 98% (`motion-safe:pointer-fine:active:scale-[0.98]`): só com mouse, nunca no toque nem com movimento reduzido. **Desabilitado** é `opacity-50` com cursor normal (`cursor-default`), sem reação a hover ou clique.

## Bordas

Dois níveis da cor primária, translúcidos, que leem igual sobre qualquer superfície e acompanham o tema sozinhos:

| Token | Valor | Uso |
|---|---|---|
| `--border` | 10% da primária | divisores de dentro de uma superfície: linhas de tabela, separadores de menu |
| `--border-strong` | 18% da primária | molduras que separam camadas: card, tabela, menu, popover, dialog, menu lateral |
| `--input` | sólida, 3:1 ou mais | borda de campo, checkbox e radio desmarcados, trilho do switch desligado |
| `--connector` | claro: `--border-strong`; escuro: `--input` | linha e anéis dos marcadores da `Timeline` |

Sem sombra, é a borda forte que separa um menu aberto do conteúdo. `--input` é sólida e mais escura porque o contorno é o que identifica um campo (WCAG 1.4.11).

## Z-index scale

Cinco camadas, cada uma reservada para um tipo de surface. Isso elimina os clássicos "guerras de z-index" que aparecem em codebases que misturam `9999`, `99`, `1`, `-1` ao gosto do dev.

| Token | Valor | Uso |
|---|---|---|
| `--z-overlay`  | `40` | Backdrop de modal (camada de escurecimento) |
| `--z-modal`    | `50` | Dialog, AlertDialog, Sheet (content), CommandPalette |
| `--z-popover`  | `60` | Popover, Combobox, DateInput |
| `--z-tooltip`  | `70` | Tooltip |
| `--z-toast`    | `80` | Sonner Toaster |

A escala é desenhada de baixo para cima:

1. **Overlay (40)** fica acima da página, abaixo de qualquer surface interativo.
2. **Modal (50)** fica acima do overlay porque o conteúdo do modal precisa receber foco e input.
3. **Popover (60)** fica acima de modal porque comboboxes e date pickers podem ser abertos *de dentro* de um Dialog.
4. **Tooltip (70)** fica acima de popover porque tooltips podem aparecer sobre qualquer trigger, inclusive triggers dentro de popovers.
5. **Toast (80)** é a camada mais alta — notificações precisam aparecer mesmo enquanto um modal está aberto. Isso explicitamente sobrescreve o default do Sonner (`999999999`), unificando a camada com o resto do sistema.

Use os utilitários Tailwind correspondentes: `z-overlay`, `z-modal`, `z-popover`, `z-tooltip`, `z-toast`.

## Fonts

Duas famílias, self-hosted para evitar dependência de CDN externo e qualquer leak de IP do usuário para o Google Fonts:

```css
--font-sans: "Geist", ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
             "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
--font-mono: "Geist Mono", ui-monospace, SFMono-Regular, "SF Mono",
             Menlo, Consolas, "Liberation Mono", monospace;
```

A fonte é carregada via `@fontsource/geist` + `@fontsource/geist-mono` no entry CSS:

```css
@import "@amfernandesinc/ui/fonts";
@import "@amfernandesinc/ui/styles";
```

**Sem CDN, sem privacy risk.** Os arquivos de fonte vão no bundle final do consumidor, servidos do próprio domínio. A fallback stack cobre o gap durante o load (sem FOIT) e degrada bem em SSR.

Para detalhes de escala tipográfica (variants, line-heights, weights), veja [Typography](?path=/docs/foundations-typography--docs).

## Placeholder

`--placeholder` é um token **separado** de `--input` (a cor da borda do input). Esse é um detalhe importante de acessibilidade:

```css
--input:       oklch(0.875 0.01 252); /* border do input */
--placeholder: oklch(0.55 0.005 252); /* texto do placeholder */
```

A regra aplicada no `@layer base`:

```css
input::placeholder,
textarea::placeholder {
  color: var(--placeholder);
}
```

A separação existe porque a cor da borda pode ser clarinha (passar despercebida visualmente), mas o placeholder precisa atingir **contraste WCAG-AA** contra o fundo branco. Com o valor atual, o placeholder atinge **4.85:1** sobre branco — acima do threshold de 4.5:1 para texto normal.

Se você precisar customizar o placeholder em um campo específico, use a classe Tailwind `placeholder:text-*` direto, mas evite reduzir o contraste abaixo de AA.
