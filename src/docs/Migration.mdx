# Migração da 0.5 para a 0.6

Tudo o que muda para um app que atualiza da 0.5.x, numa página só, com o que fazer. O `CHANGELOG.md` lista cada mudança solta; aqui estão as que pedem trabalho no app, em ordem de impacto. Cada linha cita o changeset de onde vem, com o detalhe.

## Mudanças que quebram

| Mudança | Antes (0.5) | Depois (0.6) | O que fazer |
|---|---|---|---|
| **Tokens de status claros saem** <br/>`status-solid` | `bg-status-success-bg`, `text-status-warning-text`, `border-status-info-border`… (12 tokens `--status-*-{bg,text,border}`) | Não existem mais. O Tailwind não gera classe de token que não existe: o app compila e só perde a cor, sem erro. | Procure `status-` no app. Troque por `bg-success text-success-foreground` (e `warning`, `info`, `destructive`), o fundo forte do status, ou por `<Badge variant="success" dot>` numa célula de tabela. |
| **`Sidebar` sai, entra `AppShell`** <br/>`app-shell-replaces-sidebar` | `import { Sidebar } from "@amfernandesinc/ui/sidebar"` e o `<main>` com rolagem no app | `AppShell` (`@amfernandesinc/ui/app-shell`) dono do layout | `SidebarItem` vira `AppShellItem` (o alias continua). Usuário, perfil e sair vão no `footer`. Tire o `<main>` com rolagem do app: o conteúdo vai como `children`. Sob outra barra fixa, `className="h-full"`. |
| **`Button` nasce com `type="button"`** <br/>`button-type-button` | Sem `type`, todo `Button` num `<form>` enviava o form | `type="button"` por padrão | Passe `type="submit"` no botão que envia (`<Button type="submit">Salvar</Button>`). |
| **Datas em São Paulo** <br/>`date-time-zone` | `lib/date` lia e formatava em UTC: `formatDate("2024-01-15T14:30:00Z", "brl-full")` dava `14:30` | Instantes em `America/Sao_Paulo`: o mesmo dá `11:30`; data pura (`"2024-01-15"`) nunca muda de dia | Se o backend manda data pura como instante UTC (`"2024-01-15T00:00:00.000Z"`), passe `"UTC"` como último argumento ou corte para `YYYY-MM-DD`. Revise telas que mostram hora vinda do servidor. |
| **`DateInput` digitável** <br/>`date-input-typeable` | Um `<button>`: `ref` de `HTMLButtonElement`, papel `button` | Um campo de texto `dd/mm/aaaa` com botão "Abrir calendário": `ref` de `HTMLInputElement`, papel `textbox`. Enquanto o texto não é data, o valor é `""` | `useRef<HTMLInputElement>`. Nos testes, `getByRole("textbox", { name: "Data…" })`. Quem validava só no blur passa a receber `""` a cada texto inválido. |
| **`--accent` deixa de ser cinza** <br/>`group-palette` | `bg-accent` era um cinza neutro (hover, faixa) | `--accent` é o azul do item selecionado; todas as cores mudam de valor, e `--chart-2` a `--chart-5` mudam de matiz | Onde `bg-accent` era fundo neutro, use `bg-muted`. Confira gráficos que dependiam de uma cor específica. |
| **Dois fundos** <br/>`two-backgrounds` | `bg-background` servia de superfície | `--background` é só a página; peças pintam `--card` | Um painel ou barra de filtros do app com `bg-background` passa a `bg-card border-border-strong`. |
| **Raio em três níveis** <br/>`radius-levels` | 4px em tudo | 4, 8 e 12px por papel; `rounded-md` vira 8px e `rounded-lg`+ vira 12px | Revise cantos das telas do app; prefira `rounded-inner`, `rounded-element` e `rounded-container`. |
| **Borda translúcida em dois níveis** <br/>`translucent-border`, `border-strong` | `--border` sólida, uma só | `--border` (10% da primária) nos divisores, `--border-strong` (18%) nas molduras | Molduras entre camadas: `border-border-strong`. Divisórias internas: `border-border`. Bordas de campo à mão: `border-input`. |
| **`Badge` é `<span>`** <br/>`badge-span` | `<div>` | `<span>` | `ref` de `HTMLSpanElement`; seletor `div[data-slot="badge"]` vira `[data-slot="badge"]`. |
| **`Video` mostra o quadro inteiro** <br/>`video-states` | `object-cover` fixo | `objectFit="contain"` por padrão | Para o corte antigo, `objectFit="cover"`. |
| **`Image` com `src` vazio** <br/>`image-fallback` | "Falha ao carregar imagem" | "Sem imagem" (não é erro) | Use `fallback` para personalizar. |
| **`addMonths` para no fim do mês** <br/>`add-months-month-end` | `addMonths("2024-01-31", 1)` dava 02/03/2024 | 29/02/2024 | Revise cálculos de vencimento que contavam com o estouro; num carnê, some sempre a partir da data base. |
| **Export da `DataTable` sem `xlsx`** <br/>`data-table-write-excel-file` | Usava o pacote `xlsx` (com alertas de segurança) | `write-excel-file`; datas saem no mesmo dia e hora da tabela | Nada a fazer. Se o app usava o `xlsx` que vinha junto, declare-o no app. |

## Mudanças de comportamento

Não quebram a compilação nem os tipos, mas um app pode notar.

| Mudança | O que muda |
|---|---|
| **`TimePicker` reporta a cada edição** <br/>`time-picker-on-value-change` | Apagar a hora ou digitar uma fora da faixa chama `onValueChange("")` na hora, como a documentação já dizia, em vez de esperar o campo perder o foco. |
| **`Calendar` marca o hoje de São Paulo** <br/>`calendar-today-time-zone` | O dia marcado, o mês inicial e os atalhos `"past"`, `"future"` e `"today"` de `disabledDays` seguem `America/Sao_Paulo`. Para outro fuso, passe `today`. |
| **Campo somente leitura sem placeholder** <br/>`read-only-no-placeholder` | Vazio e com `readOnly`, nenhum campo mostra a dica. |
| **`useIsMobile` certo no primeiro render** <br/>`app-shell-footer-once` | No navegador, o primeiro render já sabe se é celular (continua `false` no servidor e na hidratação). |
| **Tema escuro num ancestral** <br/>`dark-mode` | Com `dark` numa seção, os menus, popovers e dialogs abertos dali também saem escuros, e o texto solto da seção usa a cor do escuro. |

## Novidades que pedem uma decisão

- **`Schedule` e SSR** (`schedule`): os eventos aparecem em `timeZone`, São Paulo por padrão. Num app com renderização no servidor, passe `defaultDate` e `today` para o servidor mandar a agenda pronta; sem eles, a agenda chega no navegador.
- **`@source` no CSS do app** (`styles-source`): o `styles` já declara o `@source` da lib. A linha manual do app pode sair (deixá-la não atrapalha).

## Como conferir um app

1. Procure no app: `status-`, `bg-accent`, `bg-background`, `rounded-md`, `rounded-lg`, `<Sidebar`, `@amfernandesinc/ui/sidebar`, `HTMLButtonElement` perto de `DateInput`, `HTMLDivElement` perto de `Badge`, `formatDate(`, `addMonths(`.
2. Em cada `<form>`, confira que o botão de envio tem `type="submit"`.
3. Rode os testes do app: os de `DateInput` que buscavam `role="button"` acusam a mudança.
4. Olhe as telas nos dois temas: cores, cantos, bordas e fundos mudaram.
