# Hooks & helpers

Além dos 46 componentes, `@amfernandesinc/ui` exporta um conjunto pequeno e estável de hooks, utilitários de classes Tailwind, helpers financeiros (BRL/centavos), conversores de tamanho em bytes, validadores brasileiros e constantes re-exportadas de libs upstream. Esta página é a referência canônica desses símbolos.

## Sumário

| Símbolo | Tipo | O que faz |
|---|---|---|
| `useIsMobile` | hook | `true` quando a viewport é menor que 768 px (reativo a resize) |
| `useComboboxOptions` | hook | converte `Array<{ id, nome }>` em `ComboboxOption[]` memoizado |
| `cn` | function | merge de `className`s Tailwind via `clsx` + `tailwind-merge` |
| `buttonVariants` | function (CVA) | classnames do `Button` por `variant` |
| `badgeVariants` | function (CVA) | classnames do `Badge` por `variant` |
| `alertVariants` | function (CVA) | classnames do `Alert` por `variant` |
| `typographyVariants` | function (CVA) | classnames do `Typography` por `variant` |
| `tableStyles` | function | objeto com classnames para `<table>` cru |
| `toCents` | function | float reais → inteiro centavos |
| `fromCents` | function | inteiro centavos → float reais |
| `centsToDisplay` | function | centavos → string `1.234,56` |
| `formatBRL` | function | float → string `R$ 1.234,56` |
| `percentOfTotal` | function | valor a partir de % sobre um total (centavos-safe) |
| `percentFromValue` | function | % que `value` representa de `total` (2 casas) |
| `bytes`, `kb`, `mb`, `gb` | function | conversão ergonômica para bytes (binário: KiB/MiB/GiB) |
| `formatCount` | function | formata contadores capando em `max` (`"999+"`) |
| `isValidCPF`, `isValidCNPJ`, `isValidCEP`, `isValidPhone` | function | validadores brasileiros (DV oficial p/ CPF/CNPJ) |
| `defaultDataTableLabels` etc. | const | defaults pt-BR dos componentes com prop `labels` |
| `REGEXP_ONLY_DIGITS` | const | regex `/^\\d+$/` (re-export de `input-otp`) |
| `toast` | function | API imperativa de toasts (re-export de `sonner`) |

Importação genérica:

```ts
import {
  useIsMobile, useComboboxOptions,
  cn, buttonVariants, badgeVariants, alertVariants, typographyVariants, tableStyles,
  toCents, fromCents, centsToDisplay, formatBRL, percentOfTotal, percentFromValue,
  bytes, kb, mb, gb,
  formatCount,
  isValidCPF, isValidCNPJ, isValidCEP, isValidPhone,
  REGEXP_ONLY_DIGITS, toast,
} from "@amfernandesinc/ui"
```

## State hooks

### `useIsMobile`

Retorna `true` quando a viewport está abaixo do breakpoint mobile (768 px). Reativo a redimensionamento via `matchMedia` listener.

**Signature:**

```ts
function useIsMobile(): boolean
```

**Exemplo:**

```tsx
import { useIsMobile } from "@amfernandesinc/ui"

function ResponsiveNav() {
  const isMobile = useIsMobile()
  return isMobile ? <MobileDrawer /> : <DesktopSidebar />
}
```

**Notas:**

- SSR-safe: retorna `false` no primeiro render (server + hidratação), atualiza no client após o `useEffect` rodar.
- Listener é registrado uma vez por mount e removido no unmount.
- Threshold fixo em 768 px (matches `max-width: 767px`). Para customizar, use `window.matchMedia` direto em um hook próprio.
- Em ambiente de teste com jsdom, lembre-se de stubar `window.matchMedia` (já feito em `vitest.setup.ts` desta lib).

## Helpers de dados

### `useComboboxOptions`

Memoiza a transformação de um array de entidades (e.g. retorno de query) em `ComboboxOption[]`. Útil quando você consome `Combobox` com dados vindos da API no formato `{ id, nome }` (ou outro campo de label).

**Signature:**

```ts
function useComboboxOptions<
  T extends { id: number | string; nome?: string; label?: string },
>(data: T[] | undefined, labelKey?: keyof T): ComboboxOption[]
```

**Exemplo:**

```tsx
import { Combobox, useComboboxOptions } from "@amfernandesinc/ui"

type Cliente = { id: number; nome: string }

function ClienteSelect({ clientes, value, onChange }: {
  clientes: Cliente[] | undefined
  value: string
  onChange: (v: string) => void
}) {
  const options = useComboboxOptions(clientes)
  return <Combobox options={options} value={value} onValueChange={onChange} />
}
```

**Notas:**

- O `labelKey` default é `"nome"` (convenção AM). Passe outro campo se a entidade usar nome diferente: `useComboboxOptions(usuarios, "fullName")`.
- Retorna `[]` quando `data` é `undefined` (estado de loading) — `Combobox` aceita lista vazia normalmente.
- Memoizado por `data` + `labelKey`. Re-renders do componente pai não recriam o array.
- `value` é coercido para `string` via `String(item.id)` para suportar tanto `id: number` quanto `id: string`.

## Helpers de className

### `cn`

Merge inteligente de `className`s Tailwind. Combina `clsx` (concatena + descarta `false`/`null`/`undefined`) com `tailwind-merge` (resolve conflitos de classes do Tailwind — `p-2 p-4` vira `p-4`).

**Signature:**

```ts
function cn(...inputs: ClassValue[]): string
```

`ClassValue` é o tipo do `clsx`: aceita `string`, `number`, `false`, `null`, `undefined`, `Record<string, boolean>`, ou arrays aninhados.

**Exemplo:**

```tsx
import { cn } from "@amfernandesinc/ui"

function Card({ isActive, className }: { isActive?: boolean; className?: string }) {
  return (
    <div className={cn(
      "p-4 rounded-md border",
      isActive && "bg-primary text-primary-foreground",
      className, // override do consumidor vence (tailwind-merge resolve)
    )} />
  )
}
```

**Notas:**

- Sempre passe `className` do consumidor por último — o `tailwind-merge` faz a última classe ganhar.
- Use quando aplicar classes condicionais ou expor `className` como prop. Para classes estáticas, string literal basta.

### `buttonVariants`

CVA factory que gera os classnames do `Button`. Útil para estilizar elementos não-`<button>` com a aparência de botão (e.g. `<Link>` do Next.js, `<a>` cru) sem usar `asChild`.

**Signature:**

```ts
function buttonVariants(props?: {
  variant?: "default" | "destructive" | "outline" | "secondary" | "ghost" | "link"
  className?: string
}): string
```

**Exemplo:**

```tsx
import { buttonVariants, cn } from "@amfernandesinc/ui"
import Link from "next/link"

<Link
  href="/contratos"
  className={cn(buttonVariants({ variant: "outline" }))}
>
  Ver contratos
</Link>
```

**Notas:**

- Default: `variant="default"`.
- Não inclui estado `loading` (esse é gerenciado dentro de `<Button>`).
- Para combinar com classes extras, use `cn(buttonVariants(...), "minha-classe")`.

### `badgeVariants`

CVA factory para os classnames do `Badge`. Útil para elementos custom que precisam de aparência de badge.

**Signature:**

```ts
function badgeVariants(props?: {
  variant?: "default" | "secondary" | "destructive" | "outline"
  className?: string
}): string
```

**Exemplo:**

```tsx
import { badgeVariants } from "@amfernandesinc/ui"

<a href="/tag/urgente" className={badgeVariants({ variant: "destructive" })}>
  Urgente
</a>
```

### `alertVariants`

CVA factory para os classnames do `Alert`. Útil quando o consumer renderiza um wrapper próprio em vez do `<Alert>` da lib.

**Signature:**

```ts
function alertVariants(props?: {
  variant?: "default" | "info" | "success" | "warning" | "destructive"
  className?: string
}): string
```

**Exemplo:**

```tsx
import { alertVariants } from "@amfernandesinc/ui"

<section role="alert" className={alertVariants({ variant: "warning" })}>
  Operação requer aprovação manual.
</section>
```

### `typographyVariants`

CVA factory para os classnames do `Typography`. Use quando precisar aplicar a escala tipográfica em um elemento custom sem renderizar o componente.

**Signature:**

```ts
function typographyVariants(props?: {
  variant?: "heading" | "title" | "subtitle" | "lead" | "body" | "caption"
  className?: string
}): string
```

**Exemplo:**

```tsx
import { typographyVariants } from "@amfernandesinc/ui"

<dt className={typographyVariants({ variant: "caption" })}>Data</dt>
<dd className={typographyVariants({ variant: "body" })}>17/05/2026</dd>
```

### `tableStyles`

Retorna um objeto com classnames para cada parte de uma `<table>` HTML crua. Use quando `DataTable` for excessivo (e.g. tabela puramente decorativa, ou render markdown sem `react-table`).

**Signature:**

```ts
function tableStyles(): {
  table: string
  header: string
  body: string
  footer: string
  row: string
  head: string
  cell: string
  caption: string
}
```

**Exemplo:**

```tsx
import { tableStyles } from "@amfernandesinc/ui"

const t = tableStyles()

<table className={t.table}>
  <thead className={t.header}>
    <tr><th className={t.head}>Nome</th><th className={t.head}>Valor</th></tr>
  </thead>
  <tbody>
    <tr className={t.row}>
      <td className={t.cell}>Contrato A</td>
      <td className={t.cell}>R$ 1.234,56</td>
    </tr>
  </tbody>
</table>
```

**Notas:**

- Retorna o mesmo objeto em cada chamada (não memoiza, mas o objeto é trivialmente reconstruído).
- Para tabelas com sort, paginação ou filtro use `DataTable` (wrapper sobre `@tanstack/react-table`).

## Helpers BRL / financeiros

Toda aritmética financeira na lib é em **centavos inteiros**. Conversões para float acontecem só nas bordas (display ou input do usuário). Isso elimina os erros clássicos de float (`0.1 + 0.2 !== 0.3`).

### `toCents`

Float em reais para inteiro em centavos.

**Signature:**

```ts
function toCents(value: number): number
```

**Exemplo:**

```ts
import { toCents } from "@amfernandesinc/ui"

toCents(1234.56)  // 123456
toCents(0.1)      // 10
toCents(0.01)     // 1
```

**Notas:** usa `Math.round` para evitar drift de float (e.g. `1.005 * 100 = 100.49999...`).

### `fromCents`

Inteiro em centavos para float em reais.

**Signature:**

```ts
function fromCents(cents: number): number
```

**Exemplo:**

```ts
import { fromCents } from "@amfernandesinc/ui"

fromCents(123456)  // 1234.56
fromCents(10)      // 0.1
```

### `centsToDisplay`

Formata centavos como string BRL **sem** o prefixo `R$ `. Útil quando o `R$` já vem do layout (e.g. ícone, label).

**Signature:**

```ts
function centsToDisplay(cents: number): string
```

**Exemplo:**

```ts
import { centsToDisplay } from "@amfernandesinc/ui"

centsToDisplay(123456)    // "1.234,56"
centsToDisplay(-50000)    // "-500,00"
centsToDisplay(0)         // "0,00"
```

**Notas:** usa `toLocaleString("pt-BR")` para a parte de reais e padding manual para os centavos.

### `formatBRL`

Formata float em reais como string BRL **com** o prefixo `R$ `.

**Signature:**

```ts
function formatBRL(value: number): string
```

**Exemplo:**

```ts
import { formatBRL } from "@amfernandesinc/ui"

formatBRL(1234.56)   // "R$ 1.234,56"
formatBRL(0)         // "R$ 0,00"
formatBRL(-99.9)     // "R$ -99,90"
```

**Notas:** equivalente a `` `R$ ${centsToDisplay(toCents(value))}` ``.

### `percentOfTotal`

Calcula o valor a partir de um percentual sobre um total. Tudo em centavos para evitar drift.

**Signature:**

```ts
function percentOfTotal(percent: number, total: number): number
```

**Exemplo:**

```ts
import { percentOfTotal } from "@amfernandesinc/ui"

percentOfTotal(70, 185000)     // 129500
percentOfTotal(33.33, 185000)  // 61660.5 (após arredondamento em centavos)
percentOfTotal(0, 185000)      // 0
```

### `percentFromValue`

Calcula o percentual que um valor representa de um total, com 2 casas de precisão.

**Signature:**

```ts
function percentFromValue(value: number, total: number): number
```

**Exemplo:**

```ts
import { percentFromValue } from "@amfernandesinc/ui"

percentFromValue(129500, 185000)  // 70
percentFromValue(50, 200)         // 25
percentFromValue(0, 100)          // 0
percentFromValue(50, 0)           // 0 (guarda contra divisão por zero)
```

**Notas:** se `total === 0` retorna `0` em vez de `NaN`/`Infinity`. Use o par com `percentOfTotal` para roundtrip.

## Helpers de bytes

Façam expressões de tamanho de arquivo ergonômicas. Unidades **binárias** (1 KiB = 1024 B, 1 MiB = 1024 KiB, etc.) — alinhadas com o formatter usado por `FileUpload`.

**Signatures:**

```ts
function bytes(n: number): number  // identidade — só semântica
function kb(n: number): number     // n * 1024
function mb(n: number): number     // n * 1024 * 1024
function gb(n: number): number     // n * 1024 * 1024 * 1024
```

**Exemplo:**

```tsx
import { FileUpload, mb, kb, gb } from "@amfernandesinc/ui"

<FileUpload accept="image/*" maxSize={mb(2)} />
<FileUpload accept="application/pdf" maxSize={kb(500)} />
<FileUpload multiple maxSize={gb(1)} maxFiles={50} />
```

**Notas:**

- `bytes(n)` existe para legibilidade — quando você quer dizer explicitamente "isso é bytes", mas `bytes` é literalmente a função identidade.
- Para exibir tamanhos formatados, use as bibliotecas convencionais (`Intl.NumberFormat`) — a lib não exporta um `formatBytes`.

## `formatCount`

Formata um inteiro para uso em badges/contadores de notificação, capando em `max` com sufixo `+`. Útil em `<Badge>` de unread counts, "X+ resultados", indicadores em sidebar, etc.

**Signature:**

```ts
function formatCount(count: number, max?: number): string
```

- Default `max = 999`.
- `count <= max` → `String(count)`.
- `count > max` → `"${max}+"` (e.g. `"999+"`).
- `count < 0`, `NaN`, `Infinity` → `"0"` (clamped — contadores são não-negativos).

**Exemplo:**

```tsx
import { Badge, formatCount } from "@amfernandesinc/ui"

formatCount(3)         // "3"
formatCount(999)       // "999"
formatCount(1234)      // "999+"
formatCount(50, 9)     // "9+"

<Badge variant="secondary">{formatCount(unreadCount)}</Badge>
```

**Notas:**

- O input passa por `Math.floor` — `formatCount(3.9)` retorna `"3"`.
- O subpath é `@amfernandesinc/ui/lib/format-count` (também re-exportado pelo barrel).

## Validadores brasileiros

Quatro validadores puros para identificadores e contatos brasileiros. Algoritmos de CPF/CNPJ implementam o cálculo oficial dos dígitos verificadores (DV) definido pela Receita Federal — não são apenas regexes de formato.

Todos normalizam o input removendo caracteres não-numéricos antes de validar. Aceitam tanto `"123.456.789-09"` quanto `"12345678909"`.

```ts
function isValidCPF(value: string): boolean
function isValidCNPJ(value: string): boolean
function isValidCEP(value: string): boolean
function isValidPhone(value: string): boolean
```

**Importação** — subpath dedicado ou barrel, ambos funcionam:

```ts
// Subpath (recomendado quando só os validadores forem necessários)
import { isValidCPF, isValidCNPJ } from "@amfernandesinc/ui/lib/brazil"

// Barrel
import { isValidCEP, isValidPhone } from "@amfernandesinc/ui"
```

### `isValidCPF`

Valida CPF (11 dígitos) checando os dois DVs. Rejeita strings de dígitos repetidos (`"11111111111"`).

```ts
isValidCPF("123.456.789-09")   // true
isValidCPF("12345678909")      // true
isValidCPF("111.111.111-11")   // false (dígitos repetidos)
isValidCPF("123.456.789-00")   // false (DV inválido)
```

### `isValidCNPJ`

Valida CNPJ (14 dígitos) checando os dois DVs com os pesos oficiais. Também rejeita dígitos repetidos.

```ts
isValidCNPJ("11.222.333/0001-81")  // true
isValidCNPJ("11222333000181")      // true
isValidCNPJ("00.000.000/0000-00")  // false
```

### `isValidCEP`

Valida CEP — exatamente 8 dígitos numéricos. Não checa existência real do CEP (use uma API tipo ViaCEP para isso).

```ts
isValidCEP("01310-100")   // true
isValidCEP("01310100")    // true
isValidCEP("1310-100")    // false (7 dígitos)
```

### `isValidPhone`

Valida telefone brasileiro: 10 dígitos (fixo) ou 11 (celular). O DDD (primeiros 2 dígitos) deve estar entre 11 e 99.

```ts
isValidPhone("(11) 98765-4321")   // true
isValidPhone("11987654321")        // true
isValidPhone("(11) 3456-7890")    // true (fixo)
isValidPhone("9876-5432")          // false (sem DDD)
isValidPhone("(05) 98765-4321")   // false (DDD < 11)
```

**Notas:**

- Os componentes `CPFInput`, `CNPJInput`, `CEPInput` e `PhoneInput` aplicam máscara automaticamente; combine-os com esses validadores no submit ou via `react-hook-form` resolver.
- Para validação síncrona em forms, basta passar o validador no `register`:
  ```ts
  register("cpf", { validate: (v) => isValidCPF(v) || "CPF inválido" })
  ```

## i18n labels

Três componentes da lib aceitam um prop `labels?: Partial<XLabels>` para overridar strings visíveis (incluindo `aria-label`s e mensagens de estado). Defaults são em **pt-BR**.

| Componente | Type | Default constant |
|---|---|---|
| `DataTable` | `DataTableLabels` | `defaultDataTableLabels` |
| `FileUpload` | `FileUploadLabels` | `defaultFileUploadLabels` |
| `CommandPalette` | `CommandPaletteLabels` | `defaultCommandPaletteLabels` |

**Override parcial** — você só precisa passar os campos que quer mudar; o resto vem do default:

```tsx
import { DataTable } from "@amfernandesinc/ui"

<DataTable
  columns={...}
  data={...}
  labels={{
    empty: "No results.",
    paginationPrevious: "Previous",
  }}
/>
```

**Override total** — crie um objeto baseado no default e exporte para reusar:

```ts
import { defaultDataTableLabels, type DataTableLabels } from "@amfernandesinc/ui"

export const enDataTableLabels: DataTableLabels = {
  ...defaultDataTableLabels,
  search: "Search…",
  searchAriaLabel: "Search the table",
  empty: "No results.",
  loading: "Loading data…",
  paginationPrevious: "Previous page",
  paginationNext: "Next page",
  rowCount: (filtered, total) =>
    filtered === total
      ? `${total} record${total === 1 ? "" : "s"}`
      : `${filtered} of ${total} records`,
  pageIndicator: (i, n) => `Page ${i + 1} of ${n}`,
  sortBy: (header) => `Sort by ${header}`,
  exportTrigger: "Export to Excel",
  exportFiltered: "Export filtered data",
  exportPage: "Export current page",
  exportAll: "Export all data",
}
```

**Notas:**

- Todos os labels que dependem de números/contagem são **funções** (`rowCount`, `pageIndicator`, `sortBy`), não templates strings — assim você controla pluralização e ordem das palavras por idioma.
- Os tipos `DataTableLabels`, `FileUploadLabels` e `CommandPaletteLabels` ficam expostos no barrel, então da pra tipar wrappers internos da app sem importar do subpath do componente.

## Constantes re-exportadas

### `REGEXP_ONLY_DIGITS`

Re-export da constante de mesmo nome do package `input-otp`. Equivalente a `/^\\d+$/`. Use como `pattern` em `<InputOTP>` para aceitar apenas dígitos (default já é esse, mas explícito é melhor que implícito).

**Exemplo:**

```tsx
import { InputOTP, REGEXP_ONLY_DIGITS } from "@amfernandesinc/ui"

<InputOTP length={6} value={code} onValueChange={setCode} pattern={REGEXP_ONLY_DIGITS} />
```

**Outras opções:** `input-otp` também exporta `REGEXP_ONLY_CHARS` e `REGEXP_ONLY_DIGITS_AND_CHARS`. Esses não são re-exportados; importe direto de `input-otp` se precisar.

### `toast`

Re-export do `toast` do `sonner`. API imperativa para disparar notificações. Funciona em par com o componente `<Toaster />` (que deve estar montado no root da app).

**Signature (resumo):**

```ts
toast(message: string | ReactNode, options?: ToastOptions): string | number
toast.success(message, options?)
toast.error(message, options?)
toast.warning(message, options?)
toast.info(message, options?)
toast.loading(message, options?)
toast.promise(promise, { loading, success, error })
toast.dismiss(id?: string | number)
```

**Exemplo:**

```tsx
import { Toaster, toast, Button } from "@amfernandesinc/ui"

function Page() {
  return (
    <>
      <Toaster />
      <Button onClick={() => toast.success("Salvo com sucesso!")}>Salvar</Button>
    </>
  )
}
```

**Notas:**

- `<Toaster />` precisa estar no root da app (uma vez só) — sem ele, `toast()` é no-op.
- Para a API completa veja [`sonner` na NPM](https://sonner.emilkowal.ski/).

## Tipos exportados (TypeScript)

Os tipos de cada componente seguem o padrão `<Nome>Props`. Os mais úteis para reaproveitamento em código consumidor:

```ts
import type {
  ComboboxOption,
  ComboboxProps,
  DateRangeValue,
  FileUploadRejection,
  FileUploadRejectionReason,
  TableStyles,
  TreeNodeData,
  TypographyProps,
  VideoCaptionTrack,
} from "@amfernandesinc/ui"
```

Tipos `*Props` cobrem o shape público de cada componente (incluindo eventos, refs e variants do CVA). Use-os ao escrever wrappers ou HOCs em torno dos componentes da lib.
